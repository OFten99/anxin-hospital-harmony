# 真实 HIS 对接：把挂号页换成你的门诊管理系统

> 目标：鸿蒙 App 里点「挂号」，看到的是**医院数据库里的真实科室、医生、号源**，挂的号**真的写进数据库**，可以在 Web 后台「挂号管理」里查到。视觉与后台保持同一套规范。

## 二、新增的 `his.html`

位置：`entry/src/main/resources/rawfile/his.html`

## 三、后端需要的一处改动（已做）

`web_app/app.py` 加了两段，都在 `/api/mini/*` 前缀下生效，**不影响其他路由**：

1. `harden_response` 末尾追加 CORS 响应头（`Access-Control-Allow-Origin: *` 等）
2. 新增 `@app.before_request mini_api_cors_preflight()`，把 `OPTIONS` 预检直接返回 204

**为什么必须做**：WebView 加载的是本地 `rawfile`，向 `http://IP:5000` 发请求属于跨域；挂号的 JSON 提交带 `Content-Type: application/json`，会先发一次 `OPTIONS` 预检。Flask 对只声明 `GET/POST` 的路由会把 `OPTIONS` 判成 405，预检失败浏览器就直接拦掉 POST，表现为「点确认挂号没反应」。

**为什么不影响安全**：`/api/mini/*` 本来就是给外部客户端（小程序）用的接口，不走 Cookie 会话鉴权，放开 Origin 不构成会话劫持面。其余路由维持原样。

**回滚方法**：删掉 `app.py` 里 `harden_response` 末尾那个 `if request.path.startswith("/api/mini/")` 块和整个 `mini_api_cors_preflight` 函数即可。

### 实测验证结果（5001 端口临时实例，2026-10-23）

```
OPTIONS /api/mini/register   → 204 + Access-Control-Allow-Origin: *
GET     /api/mini/departments → 200 + Access-Control-Allow-Origin: *
POST    /api/mini/register {} → 200 + CORS，返回 {"code":1,"msg":"缺少 schedule_id"}
```

## 四、⚠️ 必须重启后端才生效

`app.py` 改完后，**正在运行的那个实例仍是旧代码**（实测 5000 端口返回的响应里没有 CORS 头）。

处理：把 Web 那个黑色命令行窗口关掉，重新双击 `run_web.bat`。

不重启的症状：挂号页能打开、科室列表拉不出来，WebView 控制台报 `CORS policy` 或 `Failed to fetch`。

## 五、网络前提

WebView 里的请求**不受微信域名校验限制**（那是微信客户端才有的规则），但仍受普通网络可达性约束：

- 手机与电脑必须**同一网段**
- 校园网常开 AP 隔离，手机通常访问不到电脑 → **建议手机开热点、电脑连热点**，然后用 `ipconfig` 查出电脑在热点网段的 IP，改 `AppConfig.HIS_BASE_URL`
- Windows 防火墙要放行 5000 端口

## 六、演示动线（可直接照做）

1. 电脑启动 MySQL + `run_web.bat`
2. 手机连同一网络，确认手机浏览器能打开 `http://<电脑IP>:5000`
3. 手机装 App → 语音（或点样例）说「胸口发闷，喘气费劲」
4. 分诊出「心血管内科」→ 选医院 → **进入的是 HIS 真实挂号页，直接落在内科医生列表**
5. 选张建国 → 选「2026-10-23 全天 101诊室」→ 填就诊人 → 确认挂号
6. 页面显示挂号编号与排队号
7. **切到电脑浏览器 → 登录 `admin01 / 123456` → 挂号管理 → 看到刚才这条记录**

第 7 步是这个方案的核心价值：数据真的落库了，不是界面演出来的。

## 七、两个会绊住演示的细节

### 1. 幂等限制：同一身份证当天只能挂同一医生一次

后端有幂等判断：`同一 patient.id_card + 同一 doctor_id + 当天` 已存在有效挂号时，返回「您今日已挂过该医生的号，请勿重复提交」，不会重复建档扣费。

**彩排第二遍时会被这条挡住**。三个绕法：

- 换一个身份证号（推荐，最干净）
- 换一个医生
- 到 Web 后台「挂号管理」把上一条退号

### 2. 身份证必须 18 位且能过校验

页面会先做 18 位格式检查；后端还会做业务校验。演示用身份证请用合法号码，不要随手编。

## 八、字号与适配的取舍（按你的要求做了妥协）

原设计的适老化参数（首页 40px 标题、30px 主按钮、结果页 46px 科室名）已整体收敛到与后台更接近的密度：

| 元素       | 原字号   | 现字号   |
| -------- | ----- | ----- |
| 首页主标题    | 40    | 34    |
| 主按钮文字    | 26    | 22    |
| 「帮我挂号」按钮 | 30    | 26    |
| 结果页科室名   | 46    | 36    |
| 录音计时     | 64    | 48    |
| 正文       | 20~22 | 18~19 |
| 卡片次要信息   | 19    | 17    |
| 免责声明     | 14    | 13    |

仍保留的两点：**每屏一个主操作不变**；**急症页保留红色**（`#B91C1C`）——那里若也用灰黑，「危急」就不再是危急。这是安全优先，不是视觉不统一。

如果你觉得字还是太小，改 `Index.ets` 里的 `.fontSize(n)` 即可，没有其他地方依赖这些数值。
