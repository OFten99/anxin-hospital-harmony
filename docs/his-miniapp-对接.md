# 对接自研医院小程序（HIS miniapp）

> 来源：`D:\数据库开发课程设计\医院信息系统设计开发\miniapp` 源码实读，参数均为代码中 `onLoad(options)` 实际接收的字段。

## 一、结论

**技术路径成立，但当前状态拉不起来。**

小程序结构非常适合本项目：首页就是「左科室 / 右医生」双栏，`doctors` 页接收 `department_id`，与语音分诊的输出（科室）天然对齐。一旦小程序正式上线，可做到「分诊出心血管内科 → 直达该科室医生列表」。

## 二、页面与参数（从源码提取）

| 页面 | path | 接收参数 | 用途 |
| --- | --- | --- | --- |
| 首页 | `pages/index/index` | 无 | tabBar 页，科室+医生双栏 |
| 科室医生列表 | `pages/doctors/doctors` | `department_id`、`department_name` | **推荐跳转目标** |
| 医生排班 | `pages/schedules/schedules` | `doctor_id`、`doctor_name`、`title` | 需先知道医生 ID |
| 确认挂号 | `pages/register/register` | `schedule_id`、`doctor_id`、`doctor_name`、`title`、`work_date`、`shift_type` | 最深，需已知号源 ID |
| 我的挂号 | `pages/mine/mine` | 无 | tabBar 页 |
| 挂号记录 | `pages/records/records` | 无 | — |

## 三、推荐跳转目标

```
pages/doctors/doctors?department_id={his部门ID}&department_name={科室中文名}
```

理由：
- 一跳到达"该科室有哪些医生"，老人只需选医生，不用自己找科室
- 不依赖排班/号源 ID，`department_id` 相对稳定
- 比跳到首页少两步操作

不建议直接跳 `register` 页：需要 `schedule_id`，而号源 ID 会随排班变化，客户端硬编码必然失效。

## 四、必须补的一张映射表

本项目的科室标识是字符串（`cardiology`、`orthopedics`…），你 HIS 里是数据库自增 `department_id`。两者必须建映射：

| 本项目 deptId | 科室名 | HIS department_id |
| --- | --- | --- |
| `cardiology` | 心血管内科 | 待查 |
| `neurology` | 神经内科 | 待查 |
| `orthopedics` | 骨科 | 待查 |
| … | … | … |

获取方式：起后端后请求 `GET /api/mini/departments`，把返回的 `department_id` / `department_name` 抄进表里。

**注意**：本项目的 14 个科室和你库里的科室未必一一对应（命名差异，比如你库里可能叫"心内科"、"骨外科"）。对不上的科室，跳转时要降级到首页。

## 五、当前拉不起来的三个硬条件

### 1. 没有正式小程序身份

`project.config.json` 里 `"appid": "touristappid"`——这是微信开发者工具的游客模式占位符，不是真实 AppID。你的部署说明第 4 步也写明了"注册微信小程序账号，获取正式 AppID"属于未完成事项。

没有正式 AppID，就拿不到 `gh_` 开头的**原始 ID**，而 `launchMiniProgram` 必须要它。

### 2. 没有线上版本

`launchMiniProgram` 只能拉起**已发布**的小程序，否则返回错误码 `85079 miniprogram has no online release`。沙箱调试、真机预览都不算线上版本。

### 3. 后端在内网 IP，且不满足微信域名要求

`app.js` 的 `baseUrl` 已改为 `http://10.150.5.254:5000`（校园网段）。开发者工具内可用，但真机上有两个问题：

- **体验版/正式版**：微信强制校验 request 合法域名，要求「HTTPS + 已备案域名 + 不带端口」。IP 地址直接不合格，接口会全部失败。
- **真机预览**：只要在手机微信里「打开调试」就能绕过校验，但要求手机与电脑同网段，且校园网常开 AP 隔离（手机访问不到电脑）。用手机热点让电脑连热点更稳。

彻底解决需部署到公网 HTTPS + 备案域名。操作手册见 `docs/个人小程序-体验版-取原始ID.md`。

## 六、过审与资质：正式上线这条路很窄，但你未必需要走

### 1. 个人主体做不了"在线挂号"（微信官方口径）

微信服务市场官方回复原文：

> 「appid:wxxxxxxxxxxxxxxxxx 为**个人主体类型小程序，暂不支持提供在线挂号等服务**」

这不是个别审核员的口径，是平台规则。所以以个人主体去申请「医疗服务-就医服务」类目，基本会被驳回。

### 2. 就医服务类目要求三选一的资质

微信官方给出的「医疗服务-就医服务」资质要求（三选一）：

| 方案 | 需要提供 | 对课程项目的可行性 |
| --- | --- | --- |
| a | 卫健委或医管局批文 | ❌ 不现实 |
| b | 合作医院列表 + 与一家医院的协议样本 + 该院《医疗机构执业许可证》 + 承诺书 | ⚠️ 有合作医院才行 |
| c | 开发者承诺函 + 其他平台良好经营证明（如 App Store 评分超 50 万人 + 应用内提供该类目服务截图） | ❌ 只对成熟平台开放 |

### 3. 还要先做 ICP 备案

- 自 2023-09-01 起，未上架的小程序**须完成备案后才可上架**
- 备案服务内容选到「医疗服务-就医服务」时，官方指引标注：**个人备案不建议选择**，单位备案需符合经营范围
- 流程：填写 → 平台初审（1~2 工作日）→ 工信部短信核验（24 小时内）→ 通管局审核（1~20 工作日）

**结论：正式上线需要单位主体 + 医院侧资质，周期以月计。课程项目走不通。**

### 4. 但你不需要过审：开发版/体验版也能被拉起

`launchMiniProgramReq.miniprogramType` 有三个取值：

| 值 | 版本 | 是否需要审核 |
| --- | --- | --- |
| 0 | 正式版 | ✅ 需要发布审核 |
| 1 | 开发版 | ❌ 不需要 |
| 2 | 体验版 | ❌ 不需要 |

**开发版和体验版不经审核即可拉起。** 这意味着用于自己演示/课程答辩时，完全不需要走医疗类目审核。

代价：**开发版/体验版只有该小程序的开发者、体验成员能打开**。你演示时用自己手机（既是开发者又是体验成员）没问题，但没法给别人用。

### 5. 最小可行路径（不碰医疗资质）

1. 注册**个人主体**小程序（免费，注册本身不需要医疗资质）
2. 微信开发者工具里用正式 AppID 替换 `touristappid`，上传代码为**体验版**
3. 微信公众平台 → 成员管理 → 把演示用的微信号加为**体验成员**
4. 拿到 `gh_` 开头的**原始 ID**
5. 鸿蒙侧按 `docs/miniprogram-integration.md` 接入，`miniprogramType` 填 `2`

> 前置条件：鸿蒙 App 侧仍需要在微信开放平台注册「移动应用（HarmonyOS）」并过审，这是另一个审核（不看医疗资质，主要核验应用信息）。**移动应用注册是否要求企业主体，我没有把握，请以微信开放平台当前要求为准。**


## 七、现阶段能演示什么

拉起链路没通之前，有两个可演示的替代：

1. **开发者工具内演示**：微信开发者工具打开 miniapp，勾「不校验合法域名」，走完「选科室 → 选医生 → 选号源 → 填就诊人 → 挂号」，证明业务闭环成立。
2. **鸿蒙 App 侧演示**：继续用内置模拟挂号页，证明「语音 → 分诊 → 医院列表 → 挂号页」的链路成立。

两者拼起来就是完整故事，只是中间那一步「拉起小程序」暂时是手工演示。

## 八、上线后要改的地方（一处常量）

小程序正式上线后，只需：

1. 微信开放平台注册移动应用（平台选 HarmonyOS），过审拿 `wx` 开头的移动应用 AppID
2. `module.json5` 加 `"querySchemes": ["weixin", "wxopensdk"]`
3. `oh-package.json5` 加 `@tencent/wechat_open_sdk`
4. 把 `gh_xxxxxxxx` 和 `department_id` 映射表填进 `HospitalData.ets`

客户端逻辑不用再改。代码见 `docs/miniprogram-integration.md`。
